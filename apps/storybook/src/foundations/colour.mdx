# Colour

Colour tokens are semantic: they name a job (the page background, secondary text, the fill of a primary action), not a hue. Each has a light and a dark value, and the theme switches them, so a page that uses only these tokens is correct in both themes without a second stylesheet (ADR 0016, 0017).

## Using colour

- Pick the token by its job. Text and icons use `color.fg.*`, surfaces and fills use `color.bg.*`, lines and outlines use `color.border.*`.
- A fill and the text on it are a pair: `color.accent.bg` takes `color.fg.on-accent`, `color.danger.bg` takes `color.fg.on-danger`, and so on. The pairs are checked for contrast in both themes.
- Reference a token in CSS as `var(--ave-color-bg-surface)`. Never write a raw colour, and never reference a primitive colour scale: primitives are not part of the public CSS.
- `color.brand.*` is the exact brand colour, for logos, illustrations and data marks only. Never use it for text or as a text background.
- To change the brand colour of a product or a tenant at run time, see Foundations/Brand and Guides/Theme.

## Token reference

### Surfaces and state layers (`color.bg`)

Surfaces from the canvas up to raised overlays, the state layers of hovered and pressed items, disabled fills, tracks, placeholders and the tooltip surface. In the dark theme higher surfaces are lighter.

| Token                            | CSS variable                           | Value       | Dark        | Description                                                                                                                                                                                                      |
| -------------------------------- | -------------------------------------- | ----------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `color.bg.canvas`                | `--ave-color-bg-canvas`                | `#fcf9f9`   | `#1e1b1a`   | The app background behind every surface.                                                                                                                                                                         |
| `color.bg.surface`               | `--ave-color-bg-surface`               | `#ffffff`   | `#282423`   | Content surfaces on the canvas: panels, cards, tables, form areas.                                                                                                                                               |
| `color.bg.surface-raised`        | `--ave-color-bg-surface-raised`        | `#ffffff`   | `#342f2d`   | Surfaces above the page: popovers, menus, dialogs, toasts. In dark, higher surfaces are lighter.                                                                                                                 |
| `color.bg.surface-sunken`        | `--ave-color-bg-surface-sunken`        | `#f5f3f2`   | `#1e1b1a`   | Recessed areas inside a surface: wells, code blocks, table headers.                                                                                                                                              |
| `color.bg.backdrop`              | `--ave-color-bg-backdrop`              | `#1e1b1a7a` | `#1e1b1aa3` | The scrim behind modal dialogs and drawers.                                                                                                                                                                      |

| `color.bg.track`                 | `--ave-color-bg-track`                 | `#e9e5e4`   | `#443e3c`   | The empty part of a bar that fills to show an amount: a progress bar's track.
