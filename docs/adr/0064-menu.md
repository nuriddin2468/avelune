# 0064. Menu: a menu button that draws its own trigger, Angular Aria's menu in the kit's popup, items as data

- Status: Accepted (2026-09-28, technical decision within Wave 3)
- Date: 2026-09-28
- Related: 0002, 0037, 0038, 0046, 0063; brief §6.3, §8.2, §9.1; ROADMAP.md tracked risk "iOS Safari 17–18.2 implements popover without light dismiss"

## Context

Brief §9.1 puts menu behaviour in Angular Aria. Facts, verified on 2026-09-28 (Angular Aria 22.2.0, CDK 22.2.0, Chromium 153):

- Aria's documented menu button is `ngMenuTrigger` on a button whose `menu` input is the `ngMenu` instance, and an `ngMenu` with `ngMenuItem`s inside a CDK connected overlay that opens with `trigger.expanded()`. Items inject the menu (`MENU_COMPONENT`), and the menu orders them by their place in its element.
- So the trigger and the menu must be written in one template: an application's button cannot take a menu that the kit renders, since a host directive's `menu` input cannot be set from the directive that owns it, and projected items would not find a menu the kit renders.
- Aria writes `aria-haspopup="true"`, focuses the first item on open, moves focus with the arrows, Home, End and letters, closes on Escape, on a choice and when focus leaves, and returns focus to the button.
- iOS Safari does not move focus on a tap outside, so focus leaving does not close a menu there; CDK's overlay reports an outside press (`overlayOutsideClick`).
- A view query inside `@if` is not ready during the template's first pass; a required one throws (NG0951).

## Decision

1. **`AveMenu<V>`** (`@avelune/ui/menu`, layer composites), `<ave-menu>`: `label` and `items` (required), `icon`, `variant` and `size` (Button's types), `disabled`, and the output `itemSelected: V`. Items are `AveMenuEntry<V>`: `AveMenuItem<V>` (`value`, `label`, `icon?`, `danger?`, `disabled?`) or `AveMenuSeparator` (`{ separator: true }`).
2. **The trigger is the kit's:** a `button[aveButton]` with the label and a `chevron-down`, or, with `icon`, a `button[aveIconButton]` named by `label` with `aveTooltip` of it (ADR 0063); either carries `ngMenuTrigger`, hard-disabled when `disabled`.
3. **The menu** is `ngMenu` with `ngMenuContent` in CDK's connected overlay (`aveConnectedOverlay`), named by the button, opening from the button's start or, with the new `align: 'either'`, ending at its end when there is no room. A press outside closes it through `overlayOutsideClick`, one on the button is left to Aria's toggle. The overlay's origin is the button; the host stands in before the button is drawn.
4. **Motion:** the catalog's popover classes on the menu, through `aveOverlayPresence` (ADR 0046).
5. **Look:** the popup of ADR 0046 (raised surface, `radius.lg`, `elevation.popover`, 4px of padding), at least 192px and at most `container.xs` wide; items of `control.height.md` and `radius.md`, the hover fill for hover and focus, the kit's ring inside the item (`data-focus-ring="inset"`), `danger.fg` for a destructive item, `fg.disabled` for a disabled one; separators in `border.subtle`. Forced colours: the system highlight on the item with focus.
6. **Harness:** `AveMenuHarness` (`@avelune/ui/menu/testing`): label, open, close, items, disabled items, select an item.

## Alternatives considered

- **A trigger directive on the application's button:** see above; it would need Aria's private patterns or a subclass of its directives.
- **Projected `ngMenuItem`s:** the items would be created in the application's view, outside the menu.
- **Submenus, checkbox and radio items:** Aria has them; no screen of the kit needs them yet.

## Consequences

- Popover (ADR 0065) draws its trigger the same way, so both read alike.
- A menu button's box equals a Button's; the same-size invariant covers it.
