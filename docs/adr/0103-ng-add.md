# 0103. `ng add @avelune/ui`: what it changes in an application, and how it stays repeatable

- Status: Accepted (2026-10-02, technical decision; the product owner started Phase 6)
- Date: 2026-10-02
- Related: 0007, 0018, 0023, 0030, 0032, 0089; brief §10

## Context

- Brief §10: `ng add` installs the peers, adds the global styles, the fonts and `provideAvelune()`, installs the lint configs and appends the agent snippet. ADR 0030 adds `inlineCritical: false`, `outputHashing: bundles` and the font preload; ADR 0032 and 0089 add a script that applies the stored theme and brand before the first paint.
- Angular 22.2 (verified in the installed packages, 2026-10-02):
  - `@angular/build:application` reads `index` as a string, `{ input }`, `false`, or nothing (then `<sourceRoot>/index.html`); media go to `media/` unless `outputPath.media` names another folder. `ng new` writes `outputHashing: all` in `production` and `optimization: false` in `development`, and leaves `optimization` unset elsewhere, where it means `true`.
  - `@schematics/angular/utility` has `updateWorkspace`, `addDependency` and `addRootProvider`. `addRootProvider` inserts every time it runs. CDK's own `ng add` imports the utility from the CLI's copy, without a dependency.
  - `security.autoCsp` hashes every inline script of `index.html` into the page's policy.
- `@avelune/ui` depends on `@avelune/tokens` and `@avelune/icons`; an application imports `@avelune/icons/lucide` itself to register its icons, which pnpm's strict layout allows only for a direct dependency.
- The pilot (`e-archive`, `apps/web`, read only): an Angular CLI workspace on the application builder, with `outputHashing: all`, no CSP, and `data-theme="light"` written in `index.html` because its theme service ran too late on one page.

## Decision

1. **Scope:** an application on `@angular/build:application` in an `angular.json` workspace. Any other builder or a library stops with a message that names what the kit needs (ADR 0030). Nx workspaces follow the manual steps in `docs/consumers/migration.md`.
2. **Dependencies:** `@avelune/icons` at the kit's own version, since all `@avelune/*` share one (ADR 0007); `@angular/cdk` and `@angular/aria` at the application's `@angular/core` specifier when they are missing. An existing specifier is kept.
3. **Build target:**
   - `@avelune/ui/styles.css` first in `styles`;
   - `outputHashing` `all` becomes `bundles` and `media` becomes `none`, in the options and every configuration;
   - every enabled `optimization` (unset in the options, `true`, or an object whose `styles` is not `false`) becomes an object with `styles.inlineCritical: false` and its other values kept.
4. **`index.html`:**
   - The preload of `<media>/avelune-sans-latin.woff2`: digits and punctuation are in its subset, so a screen with a number or a full stop loads it (white space alone loads no face, ADR 0088). Option `preloadCyrillic` (default `false`) preloads the Cyrillic face too, for screens in Russian or Uzbek Cyrillic.
   - The pre-paint script, `<script id="avelune-pre-paint">`, first in `<head>`. It reads `avelune:preferences` and writes the three attributes as `AveTheme` does. It applies `avelune:brand`'s stylesheet as a constructed sheet if every line passes the generator's line patterns (ADR 0089). It never checks the fingerprint, which changes with every kit version. Every storage access is guarded.
   - With `index: false` both steps are skipped with a warning.
5. **Handover:** `AveTheme` adopts the pre-painted sheet, the adopted sheet whose only rule is `@layer tokens`. It then keeps it, replaces it, or removes it when the stored fingerprint differs, so a stale brand lasts until bootstrap.
6. **CSP:** with `autoCsp` nothing more is needed. Otherwise `ng add` logs the script's `'sha256-…'` source for a policy the server sends; a `<meta>` policy in `index.html` gets it added to `script-src`.
7. **`provideAvelune()`** in the root providers through `addRootProvider`, unless a `provideAvelune` imported from `@avelune/ui/theme` is already there.
8. **Lint configs** (option `lint`, default `true`): `@avelune/eslint-config` and `@avelune/stylelint-config` as devDependencies at the kit's version. A missing `eslint.config.mjs` or `stylelint.config.mjs` at the workspace root is written; an existing one is never edited, and `ng add` logs the lines to add. The packages' contents are ADR 0104.
9. **Agent snippet** (option `agents`, default `true`): `docs/consumers/AGENTS.snippet.md`, copied into the package at build, between `<!-- avelune:start -->` and `<!-- avelune:end -->` in the workspace's `AGENTS.md`, which is created if missing.
10. **Repeatable:** a second run changes no file. A changed snippet, script or preload replaces its block in place.
11. **Tests** (`ui:test-schematics`): applications generated by `@schematics/angular` (standalone, NgModule, a custom `outputPath.media`, `index: false`, an existing provider, lint config and `AGENTS.md`, an unsupported builder), each step asserted, then the second run. A spec in `ui:test` (Chromium) runs the script's text against stored values and every preset's stylesheet, and checks that the attributes equal `AveTheme`'s. Once per change to `ng add`, the packed tarballs go into a fresh `ng new` application in the scratchpad, which builds and serves with the right first paint.

## Alternatives considered

- **Edit an existing ESLint or Stylelint config:** flat configs are arbitrary code; an edit that guesses wrong breaks a consumer's lint. Rejected for printing the lines.
- **Check the fingerprint in the script:** `ng add` would have to rewrite `index.html` on every kit version. Rejected; bootstrap corrects a stale brand.
- **The script as a global `scripts` entry:** the builder loads it after the first paint.
- **A pre-bundled stylesheet linked from `index.html`:** rejected in ADR 0030.

## Consequences

- An application whose first-visit theme is not `system` writes that `data-theme` on `<html>` in `index.html`, as the pilot does, and passes the same default to `provideAvelune`. The migration guide says so.
- The script's text is a public contract. A test pins its hash; a change fails until an `ng update` migration that replaces the block is added with it.
- Unhashed media cannot be cached as immutable (ADR 0030).
